# Atividade Prática – Controle de Versões com Git e GitHub

## 1. Introdução

A presente atividade tem como objetivo demonstrar a utilização das ferramentas Git e GitHub para o controle de versões de um projeto. Por meio da atividade, foram explorados os principais recursos de gerenciamento de repositórios, registro de alterações e criação de diferentes branches.

O Git é um sistema de controle de versões que permite acompanhar as modificações realizadas nos arquivos de um projeto. O GitHub, por sua vez, possibilita o armazenamento remoto dos repositórios, facilitando o acesso, o compartilhamento e a organização do código-fonte.

A atividade foi desenvolvida a partir da criação de um repositório público denominado `POO`, no qual foram realizadas as operações de clonagem, versionamento e gerenciamento de branches.

## 2. Criação do repositório

Inicialmente, foi criado um repositório público denominado `POO` na conta pessoal do GitHub. Esse repositório foi utilizado para armazenar os arquivos do projeto e registrar as alterações realizadas durante a atividade.

A criação do repositório permitiu estabelecer um ambiente remoto para o armazenamento do projeto, possibilitando sua atualização e consulta por meio da plataforma GitHub.

![Criação do repositório](imagens/repositorio.png)

*Figura 1 – Repositório público POO criado no GitHub.*

## 3. Clonagem do repositório

Após a criação do repositório remoto, foi realizada sua clonagem para o ambiente local. Esse procedimento permitiu obter uma cópia dos arquivos do repositório no computador, possibilitando a realização das modificações necessárias.

A clonagem também estabeleceu a conexão entre o repositório local e o remoto, permitindo que as alterações realizadas fossem posteriormente registradas e enviadas ao GitHub.

![Clonagem do repositório](imagens/clone.png)

*Figura 2 – Clonagem do repositório remoto para o ambiente local.*

## 4. Edição e versionamento dos arquivos

Com o repositório disponível localmente, foi realizada a criação e a modificação de arquivos do projeto.

As alterações foram registradas por meio de commits, que representam pontos específicos do histórico de desenvolvimento. Cada commit permite identificar as modificações realizadas, facilitando o acompanhamento da evolução do projeto.

Após o registro das alterações, os commits foram enviados ao repositório remoto, permitindo que as modificações realizadas localmente também estivessem disponíveis no GitHub.

![Versionamento dos arquivos](imagens/versionamento.png)

*Figura 3 – Registro e envio das alterações ao repositório remoto.*

## 5. Criação e alteração de branches

Durante a atividade, foi criada uma nova branch denominada `desenvolvimento`, permitindo realizar modificações de maneira independente da branch principal.

A utilização de branches possibilita organizar diferentes linhas de desenvolvimento, permitindo que novas funcionalidades sejam implementadas sem modificar diretamente a versão principal do projeto.

Na branch criada, foi realizada uma alteração em um arquivo do projeto. Posteriormente, essa modificação foi registrada em um novo commit e enviada ao repositório remoto.

Dessa forma, foi possível demonstrar a criação, a utilização e o versionamento de uma branch independente.

![Criação da branch](imagens/branch.png)

*Figura 4 – Criação e modificação da branch desenvolvimento.*

## 6. Histórico de commits e branches

O histórico de commits permite acompanhar as modificações realizadas no projeto ao longo do tempo, identificando os registros efetuados durante o desenvolvimento.

Por meio do GitHub, foi possível visualizar os commits realizados e verificar a existência das diferentes branches do repositório.

A análise do histórico possibilitou comprovar o registro das alterações e a organização do projeto em diferentes linhas de desenvolvimento.

![Histórico de commits](imagens/historico.png)

*Figura 5 – Histórico de commits e branches disponíveis no GitHub.*

## 7. Conclusão

A realização da atividade permitiu compreender os principais recursos de controle de versões disponibilizados pelo Git e pelo GitHub.

A criação e a clonagem do repositório possibilitaram estabelecer um ambiente de desenvolvimento local e remoto, enquanto o registro de commits permitiu acompanhar as modificações realizadas no projeto.

Além disso, a criação e a alteração de uma branch demonstraram como diferentes linhas de desenvolvimento podem ser utilizadas para organizar modificações de maneira independente.

Conclui-se que o Git e o GitHub são ferramentas fundamentais para o desenvolvimento de software, pois permitem manter o histórico de alterações, organizar o código-fonte e facilitar a colaboração entre desenvolvedores.
